# 验证与交付

在选择验证范围及交付结果时读取本文件。命令以根目录 [package.json](../../../../package.json) 和 [AGENTS.md](../../../../AGENTS.md) 为准。

## 按范围验证

| 改动                                  | 有效检查                                                     |
| ------------------------------------- | ------------------------------------------------------------ |
| 实体、DTO、Controller、Service 或模块 | 修改文件 lint；相关业务测试；受影响后端构建                  |
| 前端 API、类型、页面或控件            | 修改文件 lint；前端类型/构建；条件允许时验证实际交互         |
| 菜单或 SQL                            | 核对表结构、权限、组件映射与数据关联；执行过才报告数据库验证 |
| 公共包                                | 构建公共包并验证依赖它的模块                                 |
| 技能或文档                            | 内容、引用路径、元数据与格式检查                             |

公共包构建后，可用 `pnpm exec vitest run <相关测试文件>` 定向验证。测试变更使用 `pnpm test:typecheck`；HTTP/E2E 使用对应的 E2E 配置。保留项目 SWC 装饰器转换及 `test/setup.ts` 的 reflect-metadata 初始化。

根目录 `lint:*` 脚本包含写入行为，检查修改文件时优先使用 `pnpm exec eslint <文件>`、`pnpm exec stylelint <文件>` 和 `pnpm exec prettier --check <文件>`。检查通过后，只有新的改动或未解决问题需要扩大或重复验证。

交付前对照后端范例核验 Entity/DTO 校验复用、可写字段、中文列注释和业务方法说明。移动或复用校验规则时，验证字段白名单、部分更新及空值处理的实际行为。

## 业务验收

根据本次要求选择真实行为：

- 创建成功、字段校验与默认值正确；只修改允许修改的字段。
- 唯一性冲突被拒绝，编辑自身原值仍可成功；明确需要时核验并发冲突。
- 带筛选的分页、空结果及关联数据数量正确；合法的 `0` 等值没有被误删条件。
- 详情、编辑初始化和更新使用相同的业务 ID，未找到记录的行为明确。
- 关联限制拒绝删除；批量操作遇到禁止目标时，按业务约定保持原子性或明确部分成功结果。
- 表单新增/编辑切换、成功刷新、失败状态、字典及关联选择符合要求。
- 权限不足时后端实际拒绝；需要数据范围时，列表和直接按 ID 访问都符合范围。

业务规则改动需要能区分成功与拒绝路径的验证。避免只比较生成文件内容或为每个普通 Repository 调用写镜像测试。

## 交付说明

说明实际实现的操作和业务约束、关键接入位置、数据访问方式、完成的检查。SQL 未执行、服务未运行或 UI 未实测时据实列出；不能用构建通过代替运行环境已生效。
